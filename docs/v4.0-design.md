# DiseaseOntology v4.0 设计文档

> 版本：v4.0  
> 日期：2026-07-29  
> 前置版本：v3.5（备份/验证/Cypher预览/回滚）+ v3.6（关系语义）

---

## 一、版本概述

v4.0 聚焦于**多系统隔离健壮性**与**用户体验优化**，在 v3.5/v3.6 的基础上完成以下架构级改进：

| 领域 | 变更摘要 |
|------|----------|
| 多系统隔离 | 修复 API 调用层硬编码 `disease_ontology`，所有关系编辑 API 均传递 `currentSystemId` |
| 竞态条件 | GraphCanvas 引入 generation 计数器，取消系统切换后的过期异步请求 |
| 安全删除 | Neo4j 删除采用"先计数再删除"模式，新增删除前统计 API |
| 状态管理 | Store/QueryPanel 系统切换时全量清理编辑器状态，防止跨系统数据残留 |
| UI 紧凑化 | 关系编辑行内选择器统一 `size="small"` + 12px 字体 |
| 字段一致性 | 前端 `source_id`/`target_id` 统一为 `source_element_id`/`target_element_id` |

## 二、架构变化详解

### 2.1 多系统关系编辑隔离（核心修复）

#### 问题

v3.5/v3.6 中，`QueryPanel` 和 `RelationshipEditor` 的多个 API 调用**硬编码了 `'disease_ontology'`** 或未传递 `store.currentSystemId`，导致：

- 非 MED_ 系统无法编辑已有关系（实例列表从 `disease_ontology` 加载）
- 实体搜索跨系统污染（搜索结果来自 `disease_ontology`）
- 新建关系写入错误系统
- 重复检查在错误系统中执行

#### 修复方案

所有需要系统上下文的 API 调用统一传递 `store.currentSystemId`：

```
前端 API 调用链路（修复后）
┌─────────────────────────────────────────────────────────────┐
│ QueryPanel                                                  │
│  ├─ handleEntitySearch()     → searchNodes(kw, systemId)    │
│  ├─ checkInstanceDuplicate()→ checkDuplicate(..., systemId)│
│  ├─ handleRelTypeEdit()      → fetchInstances(type, sysId)  │
│  └─ handleRelTypeSave()     → createRelationship(req, id)  │
│                                                             │
│ RelationshipEditor                                          │
│  ├─ searchNodes()           → searchNodes(kw, systemId)    │
│  ├─ fetchInstances()        → fetchInstances(type, sysId)  │
│  └─ handleSave()            → createRelationship(req, id)  │
└─────────────────────────────────────────────────────────────┘
```

**涉及文件**：
- `frontend/src/components/QueryPanel/index.vue`
- `frontend/src/components/RelationshipEditor/index.vue`
- `frontend/src/api/index.ts`（API 函数签名已支持 `systemId` 参数，默认值 `'disease_ontology'`）

#### 设计原则

> **任何涉及系统数据的 API 调用，必须显式传递 `currentSystemId`，不依赖默认值。**

默认值 `'disease_ontology'` 仅用于：
- Store 初始化
- API 函数签名的 fallback
- 默认系统保护（禁止删除 `disease_ontology`）

### 2.2 竞态条件防护（GraphCanvas）

#### 问题

用户在系统 A 中点击节点触发 `fetchNeighborhood`（异步），在请求完成前切换到系统 B，系统 A 的邻居节点会合并到系统 B 的图谱中，造成**跨系统节点泄漏**。

#### 修复方案：Generation 计数器模式

```
GraphCanvas 组件
┌──────────────────────────────────────────────┐
│ let loadGeneration = 0                       │
│                                              │
│ // 节点点击 → 发起异步请求                    │
│ const myGen = loadGeneration                 │
│ const [detail, neighborData] = await ...     │
│ // 请求返回后检查代次                         │
│ if (myGen !== loadGeneration) return  // 过期│
│                                              │
│ // 系统切换 → 递增代次 + 清空状态             │
│ watch(currentSystemId) {                     │
│   loadGeneration++                           │
│   mergedNodes = []; mergedEdges = []         │
│   expandedNodes.clear()                      │
│   store.clearSelection()                     │
│   loadData()                                 │
│ }                                            │
└──────────────────────────────────────────────┘
```

**设计原则**：

> **异步请求完成后，必须检查发起时的上下文是否仍然有效。**

这是前端异步编程的标准防护模式，适用于所有涉及系统切换的异步操作。

### 2.3 安全删除模式（Neo4j + SQLite）

#### 问题

1. Cypher `DELETE r RETURN count(r)` 在 Neo4j 中返回 0（写操作 + 聚合函数的已知限制）
2. 删除前无法展示系统详细信息供用户确认
3. 删除后 SQLite 中的 `relation_semantics` 表残留数据

#### 修复方案

**后端**（`neo4j_repository.py`）：

```python
def get_system_stats(self, prefix: str) -> dict:
    """删除前统计：节点标签/数量、关系类型/数量"""
    # 只读查询，不修改数据
    ...

def delete_system_data(self, prefix: str) -> dict:
    """先计数（只读），再删除（写操作）"""
    rel_total = self.count_system_relationships(prefix)  # 只读
    node_total = self.count_system_nodes(prefix)          # 只读
    if rel_total > 0:
        self._run_write("... DELETE r", ...)              # 写
    if node_total > 0:
        self._run_write("... DETACH DELETE n", ...)       # 写
    return {"deleted_nodes": node_total, "deleted_relationships": rel_total}
```

**API 路由**（`system_router.py`）：

| 端点 | 方法 | 用途 |
|------|------|------|
| `/{system_id}/stats` | GET | 获取系统详细统计（删除前展示） |
| `/{system_id}` | DELETE | 删除 Neo4j 数据 + SQLite 清理 |

**前端**（`App.vue`）：

```
删除流程
1. 用户点击"删除" → 调用 GET /stats 获取统计
2. 弹出 Modal 展示：节点标签/数量、关系类型/数量
3. 用户输入系统名称确认（防误操作）
4. 调用 DELETE → 后端清理 Neo4j + SQLite
5. 返回 deleted_nodes / deleted_relationships / deleted_semantics
```

**设计原则**：

> **删除操作必须：① 先展示影响范围 ② 用户显式确认 ③ 返回实际删除数量 ④ 清理所有关联数据（Neo4j + SQLite）。**

### 2.4 状态管理全量清理

#### 问题

系统切换时，Store 和 QueryPanel 的编辑器状态未完全清理，导致：
- 切换后仍显示旧系统的关系编辑器
- 切换后 `editableInstances`/`relInstances` 残留旧数据
- `editingRelationship` 未清空

#### 修复方案

**Store**（`stores/index.ts`）：

```typescript
function clearSelection() {
  selectedNode.value = null
  selectedNodeDetail.value = null
  selectedRelationship.value = null
  // v4.0: 清理编辑器状态
  relationshipEditorVisible.value = false
  presetRelationshipType.value = ''
  editingRelationship.value = null
}

function closeRelationshipEditor() {
  relationshipEditorVisible.value = false
  editingRelationship.value = null  // v4.0: 补充清理
}
```

**QueryPanel**（`QueryPanel/index.vue`）：

```typescript
watch(() => store.currentSystemId, () => {
  // 清理所有详情状态
  relDetail.value = null
  isRelationNode.value = false
  detail.value = null
  detailError.value = ''
  isCategoryNode.value = false
  isRelTypeEditMode.value = false
  // v4.0: 清理编辑相关残留
  editableInstances.value = []
  relInstances.value = []
  relTypeProperties.value = {}
  // 关闭编辑器
  store.closeRelationshipEditor()
})
```

**设计原则**：

> **系统切换是"硬边界"，必须清理所有与系统上下文相关的 UI 状态。**

### 2.5 字段名一致性修复

#### 问题

前端 `handleRelTypeSave` 中使用 `source_id`/`target_id`，但后端 `CreateRelationshipRequest`/`UpdateRelationshipRequest` 模型定义的字段名为 `source_element_id`/`target_element_id`，导致内联编辑模式创建/更新关系时字段不匹配。

#### 修复

| 位置 | 修复前 | 修复后 |
|------|--------|--------|
| `QueryPanel.handleRelTypeSave` (create) | `source_id`, `target_id` | `source_element_id`, `target_element_id` |
| `QueryPanel.handleRelTypeSave` (update) | `source_id`, `target_id` | `source_element_id`, `target_element_id` |

**设计原则**：

> **前后端字段名必须严格一致，Pydantic 模型定义即契约。**

## 四、数据隔离机制

### 4.1 Prefix 驱动隔离

每个系统分配 3 字母大写前缀（如 `MED_`、`COM_`、`TUR_`），所有 Neo4j 节点标签和关系类型均以前缀开头：

```
节点标签:  MED_Disease, MED_Drug, COM_Server, TUR_City
关系类型:  MED_TREATS, MED_HAS_SYMPTOM, COM_CONNECTS_TO
```

### 4.2 前缀标准化

`normalize_prefix()` 函数确保前缀格式统一：

```
输入 "car"  → "CAR_"
输入 "MED"  → "MED_"
输入 "MED_" → "MED_"  (不变)
输入 "med"  → "MED_"  (大写)
```

保留前缀（不可用于业务系统）：`SYS_`、`META_`、`ADMIN_`

### 4.3 前端系统上下文传递

v4.0 核心改进：**所有 API 调用显式传递 `store.currentSystemId`**

```
API 函数签名（默认值仅用于 fallback）
searchNodes(keyword, systemId = 'disease_ontology')
fetchRelationshipInstances(type, systemId = 'disease_ontology')
checkRelationshipDuplicate(srcId, tgtId, relType, systemId = 'disease_ontology', excludeId = '')
createRelationship(req, systemId = 'disease_ontology')
```

## 六、v3.5 → v4.0 变更日志

### Bug 修复

1. **多系统关系编辑隔离**：修复 `searchNodes`/`fetchRelationshipInstances`/`checkRelationshipDuplicate`/`createRelationship` 未传递 `currentSystemId`，导致非 MED_ 系统无法编辑关系
2. **系统切换状态残留**：Store `clearSelection()` 和 `closeRelationshipEditor()` 未清理编辑器状态；QueryPanel 系统切换 watcher 未清理 `editableInstances`/`relInstances`/`relTypeProperties`
3. **竞态条件**：GraphCanvas 异步 `fetchNeighborhood` 在系统切换后完成，导致跨系统节点泄漏
4. **Cypher 删除语法**：`DELETE r RETURN count(r)` 返回 0，改为先计数再删除
5. **字段名不匹配**：前端 `source_id`/`target_id` 与后端 `source_element_id`/`target_element_id` 不一致
6. **SQLite 残留**：删除系统后 `relation_semantics` 表未清理

### 功能增强

1. **删除前统计展示**：新增 `GET /{system_id}/stats` 端点 + 前端 Modal 展示节点/关系详情
2. **名称输入确认**：删除系统需输入系统名称确认，防误操作
3. **删除结果反馈**：返回 `deleted_nodes`/`deleted_relationships`/`deleted_semantics`

### UI 优化

1. **关系编辑紧凑化**：`a-select` 添加 `size="small"`，字体统一 12px，弹窗选项同步紧凑
2. **关系类型标签紧凑化**：`a-tag` 字体 12px，padding 压缩
