## 1. 核心设计决策

### 1.1 双层存储架构

v3.0 采用 **SQLite + Neo4j** 双层存储，各司其职：

```
┌─────────────────────────────────────────────────────┐
│                    SQLite (本地)                      │
│                                                     │
│  职责：系统元数据管理                                  │
│  ┌───────────────────────────────────────────────┐  │
│  │  systems 表                                     │  │
│  │  ├─ system_id    (PK)    系统唯一标识            │  │
│  │  ├─ name                 系统显示名称            │  │
│  │  ├─ description          系统备注描述            │  │
│  │  ├─ prefix               Neo4j 标签前缀          │  │
│  │  ├─ node_count           节点统计数              │  │
│  │  ├─ relationship_count   关系统计数              │  │
│  │  ├─ import_source        数据来源                │  │
│  │  ├─ created_at           创建时间                │  │
│  │  └─ updated_at           更新时间                │  │
│  └───────────────────────────────────────────────┘  │
└───────────────────────┬─────────────────────────────┘
                        │  prefix 映射
                        ▼
┌─────────────────────────────────────────────────────┐
│                 Neo4j (Community)                     │
│                                                     │
│  职责：知识图谱数据存储（通过前缀隔离多套图谱）         │
│  ┌───────────────────────────────────────────────┐  │
│  │  系统 A (MED_)                                  │  │
│  │  (:MED_Disease)─[:MED_TREATS]→(:MED_Drug)      │  │
│  │  (:MED_Symptom)─[:MED_MANIFESTS_IN]→(:MED_Disease) │
│  │                                               │  │
│  │  系统 B (BIO_)                                  │  │
│  │  (:BIO_Species)─[:BIO_BELONGS_TO]→(:BIO_Genus) │  │
│  └───────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────┘
```

**设计理由**：

| 问题 | 解决方案 |
|------|----------|
| Neo4j Community 不支持多数据库 | 使用**标签/关系类型前缀**实现物理级隔离 |
| 需要记录有多少套图谱、每套叫什么 | 使用 **SQLite** 管理系统元数据（轻量、零配置） |
| 前缀需要全局唯一且持久化 | SQLite 中 `systems.prefix` 有 UNIQUE 约束 |
| 启动时需要展示系统列表 | 启动时读取 SQLite，显示在左上角下拉框 |

**与上一版的根本区别**：

| 维度 | 上一版设计 | 新版设计 |
|------|-----------|---------|
| 系统元数据存储 | Neo4j `System` 节点 | SQLite `systems` 表 |
| 系统创建 | 在 Neo4j 中建 System 节点 | 在 SQLite 中插一行 + 分配 prefix |
| 系统删除 | DETACH DELETE Neo4j 节点 | SQLite 删行 + Neo4j 删业务数据 |
| 启动流程 | 读取 Neo4j System 节点 | 读取 SQLite systems 表 |
| 依赖 | 仅 Neo4j | SQLite（元数据）+ Neo4j（图谱数据） |

### 1.2 Neo4j 多系统数据隔离方案：前缀隔离

**背景**：Neo4j Community Edition **不支持多数据库**，一个实例只能有一个数据库。

**决策：基于前缀的标签/关系类型隔离（Prefix-based Label Isolation）**

```
方案对比：
┌──────────────────┬──────────────────┬──────────────────┬─────────────────────┐
│ 方案             │ 属性隔离 (system_id)│ 多数据库隔离      │ 前缀隔离 ★ 最终选择   │
├──────────────────┼──────────────────┼──────────────────┼─────────────────────┤
│ 实现方式         │ system_id 属性    │ 每个系统独立 DB   │ Label/Type 加前缀     │
│ 隔离程度         │ ⚠️ 弱(需WHERE过滤) │ 强                │ ✅ 强(物理级隔离)     │
│ 查询性能         │ ⚠️ 每次需WHERE    │ 好                │ ✅ 好(索引天然隔离)   │
│ Community兼容    │ ✅               │ ❌ 不支持多DB     │ ✅                   │
│ 查询复杂度       │ 中               │ 低                │ ✅ 低(无需WHERE)      │
│ 数据迁移成本     │ 低               │ 无                │ ⚠️ 中(重命名标签)     │
│ 跨系统误写风险   │ ⚠️ 存在(忘加WHERE) │ 无               │ ✅ 无(标签级隔离)     │
└──────────────────┴──────────────────┴──────────────────┴─────────────────────┘
```

**核心机制**：

```
系统 A (疾病诊疗) prefix = "MED_"  ← 存储在 SQLite systems 表
  节点标签:  MED_Disease, MED_Symptom, MED_Drug, MED_BodyPart, MED_SideEffect
  关系类型:  MED_SUB_CLASS_OF, MED_MANIFESTS_IN, MED_TREATS, ...

系统 B (生物分类) prefix = "BIO_"  ← 存储在 SQLite systems 表
  节点标签:  BIO_Species, BIO_Genus, BIO_Family, BIO_Order, ...
  关系类型:  BIO_BELONGS_TO, BIO_EVOLVED_FROM, BIO_CLASSIFIED_AS, ...

系统 C (企业知识) prefix = "ENT_"  ← 存储在 SQLite systems 表
  节点标签:  ENT_Company, ENT_Person, ENT_Product, ENT_Department, ...
  关系类型:  ENT_EMPLOYS, ENT_PRODUCES, ENT_SUBSIDIARY_OF, ...
```

**关键设计原则**：

- 每个系统分配一个唯一的 `prefix`（如 `MED_`、`BIO_`），约定使用大写字母 + 下划线结尾
- 前缀信息由 **SQLite 统一管理**，Neo4j 中不再存储 System 元数据节点
- 同一系统中，所有节点标签和关系类型都以该前缀开头
- 系统切换 = 从 SQLite 查出当前系统的 `prefix`，所有 Neo4j 查询动态拼接
- 前端展示时自动剥离前缀（`MED_Disease` → `Disease`），对用户透明

### 1.3 关系数据库接口技术选型

使用 **SQLAlchemy 2.0** 统一管理 SQLite，同时服务于数据导入引擎（对接 MySQL/PostgreSQL/SQL Server 等外部数据源）。

### 3.4 前缀命名规范

| 规则 | 说明 | 示例 |
|------|------|------|
| 大写字母 | 仅使用大写拉丁字母 A-Z | `MED_`, `BIO_` |
| 下划线结尾 | 必须以 `_` 结尾 | `MED_`, `ENT_` |
| 长度 3-6 | 前缀部分 2-5 个字符 + `_` | `MED_`(4), `SPORT_`(6) |
| 唯一性 | 全局不重复（SQLite UNIQUE 约束保证） | - |
| 语义关联 | 建议与系统名称相关 | 医疗→MED, 生物→BIO |

**保留前缀**（不可用于业务系统）：

- `SYS_` — 平台系统级操作
- `META_` — 元数据
- `ADMIN_` — 管理功能

### 3.5 前缀生成规则

```python
# backend/services/system_service.py

import re

@staticmethod
def _generate_prefix(name: str, existing_prefixes: set[str]) -> str:
    """根据系统名称自动生成唯一前缀。

    规则：
    1. 提取英文单词首字母或中文拼音首字母
    2. 大写并加下划线结尾
    3. 检测冲突，冲突时调整
    """
    # 提取英文字母
    chars = re.findall(r'[A-Za-z]', name)
    if chars:
        prefix = "".join([c.upper() for c in chars[:3]])
    else:
        # 纯中文：取拼音首字母映射（简化处理）
        prefix = "KG"  # Knowledge Graph fallback

    prefix = f"{prefix}_"

    # 冲突处理
    if prefix in existing_prefixes:
        for i in range(2, 10):
            alt = f"{prefix[:-1]}{i}_"
            if alt not in existing_prefixes:
                return alt
        # 极端情况：随机
        import random, string
        prefix = "".join(random.choices(string.ascii_uppercase, k=3)) + "_"

    return prefix
```

### 3.7 标签/类型名称转换工具

```python
# backend/utils/label_utils.py (新增)

def strip_prefix(label: str, prefix: str) -> str:
    """剥离去前缀，用于前端展示。

    Examples:
        strip_prefix("MED_Disease", "MED_") → "Disease"
        strip_prefix("MED_SUB_CLASS_OF", "MED_") → "SUB_CLASS_OF"
    """
    if label.startswith(prefix):
        return label[len(prefix):]
    return label


def add_prefix(label: str, prefix: str) -> str:
    """添加前缀，用于构造 Cypher 查询。

    Examples:
        add_prefix("Disease", "MED_") → "MED_Disease"
        add_prefix("TREATS", "MED_") → "MED_TREATS"
    """
    if label.startswith(prefix):
        return label  # 已有前缀，不重复添加
    return f"{prefix}{label}"


def extract_all_short_labels(prefixed_labels: list[str], prefix: str) -> list[str]:
    """从带前缀的标签列表中批量剥离前缀。

    Examples:
        extract_all_short_labels(
            ["MED_Disease", "MED_Symptom", "MED_Drug"], "MED_"
        ) → ["Disease", "Symptom", "Drug"]
    """
    result = []
    for label in prefixed_labels:
        if label.startswith(prefix):
            short = label[len(prefix):]
            if short:
                result.append(short)
    return result
```

```python
from sqlalchemy import create_engine, Engine
from sqlalchemy.orm import sessionmaker, Session

from backend.models.system import Base

_engine: Engine | None = None
_SessionLocal: sessionmaker | None = None


def get_engine(db_path: str) -> Engine:
    """获取或创建 SQLAlchemy 引擎（单例）."""
    global _engine
    if _engine is None:
        _engine = create_engine(
            f"sqlite:///{db_path}",
            echo=False,
            connect_args={"check_same_thread": False},  # FastAPI 多线程兼容
        )
    return _engine


def init_database(db_path: str) -> None:
    """初始化 SQLite 数据库：
    1. 创建所有表
    2. 插入默认系统数据（如果不存在）
    """
    engine = get_engine(db_path)
    # 创建表
    Base.metadata.create_all(bind=engine)

    # 种子数据：默认的疾病诊疗系统
    session = get_session()
    try:
        from backend.models.system import SystemModel
        existing = session.query(SystemModel).filter_by(
            system_id="disease_ontology"
        ).first()
        if not existing:
            default = SystemModel(
                system_id="disease_ontology",
                name="疾病诊疗知识图谱",
                description="包含疾病、药物、症状、副作用、身体部位及其关系的疾病诊疗知识图谱",
                prefix="MED_",
                import_source="原生数据",
            )
            session.add(default)
            session.commit()
            print("✅ SQLite: 默认系统 '疾病诊疗知识图谱' (MED_) 已创建")
    finally:
        session.close()


def get_session() -> Session:
    """获取一个新的 SQLAlchemy Session."""
    global _SessionLocal
    if _SessionLocal is None:
        raise RuntimeError("数据库未初始化，请先调用 init_database()")
    return _SessionLocal()
```

```python
# backend/services/system_service.py ★ 重写

from sqlalchemy.orm import Session

from backend.database import get_session
from backend.models.system import SystemModel, SystemInfo


class SystemService:
    """系统管理服务 —— 基于 SQLite 存储元数据"""

    # ───────────── 查询 ─────────────

    def get_all_systems(self) -> list[SystemInfo]:
        """获取所有系统列表（从 SQLite）."""
        session = get_session()
        try:
            rows = session.query(SystemModel).order_by(
                SystemModel.created_at.desc()
            ).all()
            return [self._to_info(r) for r in rows]
        finally:
            session.close()

    def get_system(self, system_id: str) -> SystemInfo | None:
        """获取单个系统信息."""
        session = get_session()
        try:
            row = session.query(SystemModel).filter_by(
                system_id=system_id
            ).first()
            return self._to_info(row) if row else None
        finally:
            session.close()

    def get_prefix(self, system_id: str) -> str:
        """根据 system_id 获取 prefix."""
        system = self.get_system(system_id)
        if not system:
            raise ValueError(f"系统 '{system_id}' 不存在")
        return system.prefix

    # ───────────── 写操作 ─────────────

    def create_system(self, name: str, description: str,
                      prefix: str = "", import_source: str = "manual") -> SystemInfo:
        """创建新系统（写入 SQLite）.

        自动分配 prefix 如果用户未指定。
        """
        session = get_session()
        try:
            # 生成唯一的 system_id 和 prefix
            system_id = self._slugify(name)
            if not prefix:
                existing_prefixes = {
                    s.prefix for s in session.query(SystemModel).all()
                }
                prefix = self._generate_prefix(name, existing_prefixes)

            # 确保 system_id 唯一
            existing = session.query(SystemModel).filter_by(
                system_id=system_id
            ).first()
            if existing:
                from datetime import datetime
                system_id = f"{system_id}_{datetime.now().strftime('%Y%m%d%H%M%S')}"

            model = SystemModel(
                system_id=system_id,
                name=name,
                description=description,
                prefix=prefix,
                import_source=import_source,
            )
            session.add(model)
            session.commit()
            session.refresh(model)
            return self._to_info(model)
        finally:
            session.close()

    def delete_system(self, system_id: str) -> bool:
        """删除系统（SQLite 删记录 + 通知调用方清理 Neo4j 数据）."""
        session = get_session()
        try:
            row = session.query(SystemModel).filter_by(
                system_id=system_id
            ).first()
            if not row:
                return False
            session.delete(row)
            session.commit()
            return True
        finally:
            session.close()

    def update_counts(self, system_id: str,
                      node_count: int, relationship_count: int) -> None:
        """更新系统节点/关系统计."""
        session = get_session()
        try:
            row = session.query(SystemModel).filter_by(
                system_id=system_id
            ).first()
            if row:
                row.node_count = node_count
                row.relationship_count = relationship_count
                session.commit()
        finally:
            session.close()

    # ───────────── 工具 ─────────────

    def _to_info(self, model: SystemModel) -> SystemInfo:
        """ORM 模型 → Pydantic 模型."""
        return SystemInfo(
            system_id=model.system_id,
            prefix=model.prefix,
            name=model.name,
            description=model.description or "",
            node_count=model.node_count or 0,
            relationship_count=model.relationship_count or 0,
            created_at=model.created_at or "",
            updated_at=model.updated_at or "",
            import_source=model.import_source or "manual",
        )

    def _slugify(self, name: str) -> str:
        """将系统名称转为合法的 system_id."""
        import re
        slug = name.lower().strip()
        slug = re.sub(r'\s+', '_', slug)
        slug = re.sub(r'[^a-z0-9_]', '', slug)
        return slug or "unnamed_system"

    def _generate_prefix(self, name: str, existing: set[str]) -> str:
        """根据系统名称自动生成唯一前缀."""
        import re
        chars = re.findall(r'[A-Za-z]', name)
        if chars:
            prefix = "".join([c.upper() for c in chars[:3]])
        else:
            prefix = "KG"
        prefix = f"{prefix}_"
        if prefix in existing:
            for i in range(2, 10):
                alt = f"{prefix[:-1]}{i}_"
                if alt not in existing:
                    return alt
        return prefix
```

```python
def get_all_nodes(self, prefix: str, limit: int = 200) -> list[dict]:
    """获取当前系统内所有节点（通过前缀过滤）。"""
    return self._run(
        "MATCH (n) "
        "WHERE ANY(label IN labels(n) WHERE label STARTS WITH $prefix) "
        "RETURN elementId(n) AS id, n.name AS label, "
        "  [l IN labels(n) WHERE l STARTS WITH $prefix][0] AS type "
        "LIMIT $limit",
        prefix=prefix, limit=limit,
    )

def get_all_edges(self, prefix: str, limit: int = 500) -> list[dict]:
    """获取当前系统内所有边（通过前缀过滤关系类型）。"""
    return self._run(
        "MATCH (a)-[r]->(b) "
        "WHERE type(r) STARTS WITH $prefix "
        "RETURN elementId(r) AS id, "
        "elementId(a) AS source, elementId(b) AS target, "
        "type(r) AS type "
        "LIMIT $limit",
        prefix=prefix, limit=limit,
    )

def get_node_labels(self, prefix: str) -> list[dict]:
    """获取当前系统内所有节点标签及实例数量."""
    return self._run(
        "MATCH (n) "
        "WHERE ANY(label IN labels(n) WHERE label STARTS WITH $prefix) "
        "RETURN DISTINCT "
        "  [l IN labels(n) WHERE l STARTS WITH $prefix][0] AS label, "
        "  count(*) AS count "
        "ORDER BY count DESC",
        prefix=prefix,
    )

def search_nodes(self, keyword: str, prefix: str) -> list[dict]:
    """在当前系统中搜索节点（模糊匹配 name）。"""
    query = """
        MATCH (n)
        WHERE n.name CONTAINS $keyword
          AND ANY(label IN labels(n) WHERE label STARTS WITH $prefix)
        RETURN elementId(n) AS element_id,
               labels(n) AS labels,
               n.name AS name,
               properties(n) AS properties
        LIMIT 50
    """
    return self._run(query, keyword=keyword, prefix=prefix)

def get_nodes_by_label(self, label: str, prefix: str,
                       limit: int = 200, offset: int = 0) -> list[dict]:
    """分页获取指定标签的节点实例。label 为短标签名（如 'Disease'）。"""
    full_label = f"{prefix}{label}"
    return self._run(
        f"MATCH (n:`{full_label}`) "
        "RETURN elementId(n) AS element_id, labels(n) AS labels, "
        "n.name AS name "
        "ORDER BY n.name "
        "SKIP $offset LIMIT $limit",
        offset=offset, limit=limit,
    )

def get_relationships_for_node(self, element_id: str, prefix: str) -> list[dict]:
    """获取节点的所有关系（仅包含当前系统前缀的关系类型）."""
    query = """
        MATCH (n)-[r]-(m)
        WHERE elementId(n) = $eid
          AND type(r) STARTS WITH $prefix
        RETURN type(r) AS rel_type,
               [l IN labels(m) WHERE l STARTS WITH $prefix][0] AS target_label,
               m.name AS target_name,
               elementId(m) AS target_element_id,
               elementId(r) AS rel_element_id,
               properties(r) AS properties
    """
    return self._run(query, eid=element_id, prefix=prefix)

def create_node(self, label: str, properties: dict, prefix: str) -> dict:
    """创建实体节点。label 为短标签名，内部拼接前缀。"""
    full_label = f"{prefix}{label}"
    return self._run_write(
        f"CREATE (n:`{full_label}` {{name: $name}}) "
        "SET n += $properties "
        "RETURN elementId(n) AS element_id, labels(n) AS labels, "
        "properties(n) AS properties",
        {"name": properties.get("name", ""), "properties": properties},
    )[0]

def create_relationship(self, source_eid: str, target_eid: str,
                        rel_type: str, properties: dict,
                        prefix: str) -> dict:
    """创建关系。rel_type 为短类型名，内部拼接前缀。"""
    full_type = f"{prefix}{rel_type}"
    return self._run_write(
        f"MATCH (s) WHERE elementId(s) = $src "
        f"MATCH (t) WHERE elementId(t) = $tgt "
        f"CREATE (s)-[r:`{full_type}`]->(t) "
        f"SET r += $props "
        "RETURN elementId(r) AS rel_element_id, type(r) AS rel_type, "
        "properties(r) AS properties",
        {"src": source_eid, "tgt": target_eid, "props": properties or {}},
    )[0]
```

```
                         批量写入关系（type + prefix）    → CREATE (s)-[:`BIO_TREATS`]->(t)
                              ↓
                         更新统计                         → UPDATE systems SET node_count=...
                              ↓
                         返回 SystemInfo    ←─────────
自动切换新系统     ←─────────
```

### 6.2 ImportService 改造

```python
class ImportService:
    def import_from_excel(self, file_bytes: bytes, system_name: str,
                          description: str, prefix: str = "") -> SystemInfo:
        # 1. 在 SQLite 中注册新系统（含 prefix）
        system = self._system_svc.create_system(
            name=system_name,
            description=description,
            prefix=prefix,           # 空则自动生成
            import_source="excel",
        )

        # 2. 解析 Excel
        preview = self._parse_excel(file_bytes)

        # 3. 写入 Neo4j（使用 SQLite 中记录的 prefix）
        for entity in preview.entities:
            self._repo.create_node(
                label=entity["label"],           # 短名: "Disease"
                properties=entity["properties"],
                prefix=system.prefix,            # → "MED_Disease"
            )

        for rel in preview.relationships:
            self._repo.create_relationship(
                source_eid=rel["source_eid"],
                target_eid=rel["target_eid"],
                rel_type=rel["type"],            # 短名: "TREATS"
                properties=rel.get("properties", {}),
                prefix=system.prefix,            # → "MED_TREATS"
            )

        # 4. 更新 SQLite 统计
        self._update_system_stats(system.system_id)
        return system
```

## 8. 迁移方案

### 8.1 迁移概述

v3.0 迁移包含两个独立部分：

| 迁移内容 | 存储层 | 说明 |
|---------|--------|------|
| **Part A: SQLite 初始化** | SQLite | 建表 + 插入默认系统记录 (MED_) |
| **Part B: Neo4j 前缀迁移** | Neo4j | 标签重命名 + 关系类型重建 + 移除 system_id |

两部分均**幂等执行**，重复运行安全。

### 8.2 迁移流程

```
启动时:
  ├─ Part A: SQLite 初始化（database.py → init_database）
  │    ├─ CREATE TABLE IF NOT EXISTS systems
  │    └─ INSERT OR IGNORE 默认系统 (MED_)
  │
  └─ Part B: Neo4j 前缀迁移（migration.py → run_migration）
       ├─ 检查是否已迁移（MED_ 标签是否存在）
       ├─ 步骤 1: 迁移关系类型（先做，需要旧标签 MATCH）
       │    SUB_CLASS_OF → MED_SUB_CLASS_OF
       │    MANIFESTS_IN → MED_MANIFESTS_IN
       │    ...
       ├─ 步骤 2: 迁移节点标签
       │    SET n:MED_Disease REMOVE n:Disease
       │    ...
       ├─ 步骤 3: 移除节点 system_id 属性
       └─ 步骤 4: 更新 SQLite 中的统计数字
```

### 8.3 Part B: Neo4j 标签迁移

```cypher
-- 标签重命名（Native Cypher）
MATCH (n:Disease)
SET n:MED_Disease
REMOVE n:Disease
```

### 8.4 Part B: Neo4j 关系类型迁移

```cypher
-- 关系类型无法直接重命名，需删除重建
MATCH (s:Symptom)-[r:MANIFESTS_IN]->(d:Disease)
CREATE (s)-[r_new:MED_MANIFESTS_IN]->(d)
SET r_new = properties(r)
DELETE r
```

**关键：关系迁移必须在标签迁移之前完成**（因为 MATCH 需要旧标签名来匹配节点模式）。

### 8.5 完整迁移脚本

```python
# backend/migration.py ★ 重写

from neo4j import GraphDatabase
from backend.config import settings

# 标签映射: old_label → new_label
LABEL_MAPPINGS = {
    "Disease":      "MED_Disease",
    "Symptom":      "MED_Symptom",
    "Drug":         "MED_Drug",
    "BodyPart":     "MED_BodyPart",
    "SideEffect":   "MED_SideEffect",
}

# 关系类型映射: old_type → new_type
REL_MAPPINGS = {
    "SUB_CLASS_OF":         "MED_SUB_CLASS_OF",
    "MANIFESTS_IN":         "MED_MANIFESTS_IN",
    "TREATS":               "MED_TREATS",
    "CONTRAINDICATED_WITH": "MED_CONTRAINDICATED_WITH",
    "CAN_SUBSTITUTE":       "MED_CAN_SUBSTITUTE",
    "AFFECTS":              "MED_AFFECTS",
    "HAS_SIDE_EFFECT":      "MED_HAS_SIDE_EFFECT",
}

DEFAULT_PREFIX = "MED_"
DEFAULT_SYSTEM_ID = "disease_ontology"


def run_migration() -> bool:
    """执行 Neo4j v2.0 → v3.0 前缀迁移（幂等）."""
    if not settings.neo4j_uri:
        print("⚠️  未配置 Neo4j URI，跳过 Neo4j 迁移")
        return False

    driver = GraphDatabase.driver(
        settings.neo4j_uri,
        auth=(settings.neo4j_user, settings.neo4j_password),
    )

    try:
        with driver.session() as session:

            # ---- 检查是否已迁移 ----
            check = session.run(
                "MATCH (n:MED_Disease) RETURN n LIMIT 1"
            )
            if check.single():
                print("✅ Neo4j 已使用前缀（MED_ 标签存在），跳过迁移")
                return False

            print("🚀 开始 Neo4j 数据迁移: v2.0 → v3.0 (MED_ 前缀隔离)")

            # ---- 步骤 1: 迁移关系类型 ----
            print("\n📌 步骤 1: 迁移关系类型...")
            total_rels = 0
            for old_type, new_type in REL_MAPPINGS.items():
                result = session.run(f"""
                    MATCH (a)-[r:`{old_type}`]->(b)
                    CREATE (a)-[r_new:`{new_type}`]->(b)
                    SET r_new = properties(r)
                    DELETE r
                    RETURN count(r_new) AS migrated
                """)
                count = result.single()["migrated"]
                total_rels += count
                if count > 0:
                    print(f"  {old_type:25s} → {new_type:25s} ({count} 条)")

            print(f"  共迁移 {total_rels} 条关系")

            # ---- 步骤 2: 迁移节点标签 ----
            print("\n📌 步骤 2: 迁移节点标签...")
            total_nodes = 0
            for old_label, new_label in LABEL_MAPPINGS.items():
                result = session.run(f"""
                    MATCH (n:`{old_label}`)
                    SET n:`{new_label}`
                    REMOVE n:`{old_label}`
                    RETURN count(n) AS migrated
                """)
                count = result.single()["migrated"]
                total_nodes += count
                if count > 0:
                    print(f"  {old_label:15s} → {new_label:15s} ({count} 个)")

            print(f"  共迁移 {total_nodes} 个节点")

            # ---- 步骤 3: 移除 system_id 属性 ----
            print("\n📌 步骤 3: 移除节点 system_id 属性...")
            result = session.run("""
                MATCH (n)
                WHERE n.system_id IS NOT NULL
                REMOVE n.system_id
                RETURN count(n) AS cleaned
            """)
            cleaned = result.single()["cleaned"]
            print(f"  已从 {cleaned} 个节点移除 system_id 属性")

            # ---- 步骤 4: 更新 SQLite 统计 ----
            print("\n📌 步骤 4: 更新 SQLite 系统统计...")
            node_count = session.run("""
                MATCH (n)
                WHERE ANY(l IN labels(n) WHERE l STARTS WITH $prefix)
                RETURN count(n) AS cnt
            """, prefix=DEFAULT_PREFIX).single()["cnt"]

            rel_count = session.run("""
                MATCH ()-[r]->()
                WHERE type(r) STARTS WITH $prefix
                RETURN count(r) AS cnt
            """, prefix=DEFAULT_PREFIX).single()["cnt"]

            # 更新 SQLite
            from backend.services.system_service import SystemService
            svc = SystemService()
            svc.update_counts(DEFAULT_SYSTEM_ID, node_count, rel_count)

            print(f"\n🎉 Neo4j 迁移完成: "
                  f"prefix='{DEFAULT_PREFIX}', "
                  f"{node_count} 节点, {rel_count} 关系")
            return True

    finally:
        driver.close()
```

### 8.6 启动时的迁移检查


## 10. 总结

### 10.1 核心设计要点

1. **双层存储**：SQLite 管元数据（有哪些系统、每个系统的 prefix），Neo4j 管图谱数据
2. **前缀隔离**：通过标签/关系类型前缀实现 Neo4j Community 的多图谱物理级隔离
3. **启动加载**：系统启动时首先读取 SQLite，将系统列表传给前端下拉框
4. **透明展示**：前端自动剥离前缀（`MED_Disease` → `Disease`），用户无感
5. **唯一约束**：SQLite 中 `prefix` 字段有 UNIQUE 约束，防止前缀冲突

### 10.2 数据流向

```
用户选择系统          前端传递 system_id
    │                      │
    ▼                      ▼
SQLite systems 表    Router 层
    │                 │
    │  查得 prefix     │
    ▼                 ▼
Neo4j               Service 层 (用 prefix 拼接标签)
    │
    ▼
返回业务数据 → 前端展示（剥离前缀）
```

### 10.3 删除 Neo4j System 节点

v3.0 迁移完成后，Neo4j 中的 `System` 节点不再使用：

- 迁移脚本会在步骤3中移除所有节点的 `system_id` 属性
- 如果之前版本创建了 `System` 节点，迁移后这些节点可以通过手动清理删除
- 所有系统元数据查询均通过 SQLite 完成，不再依赖 Neo4j 中的 System 节点
