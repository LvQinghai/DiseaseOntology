## 1. 版本目标

v2.0 在 v1.0 的"只读浏览"基础上，增加**编辑能力**，实现以下功能：

| 功能 | 描述 | 优先级 |
|------|------|--------|
| **实体（节点）管理** | 新增、编辑、删除本体节点 | P0 |
| **属性管理** | 对节点的属性进行增删改 | P0 |
| **关系管理** | 创建、编辑、删除节点间的关系 | P0 |
| **跨标签关系** | 支持在不同的本体类型之间建立关系（如 Disease→Symptom） | P1 |
| **批量导入** | 从文件批量导入节点和关系 | P2 |

**核心原则**：
- 所有编辑操作实时同步到 Neo4j，不依赖前端缓存
- 编辑后自动刷新受影响的视图（树、详情面板、图谱）
- 危险操作（删除）必须有二次确认

### 3.2 Service 层 (`editor_service.py`)

```python
class EditorService:
    """本体编辑器服务 —— 包含业务校验逻辑"""

    def __init__(self, repo: Neo4jRepository):
        self._repo = repo

    # ----- 实体 -----
    def create_entity(self, req: CreateEntityRequest) -> EntityResponse:
        """
        1. 校验必填字段 name
        2. 检查同名节点是否已存在（可选）
        3. 调用 repo.create_node()
        4. 返回新节点的完整信息
        """

    def update_entity(self, req: UpdateEntityRequest) -> EntityResponse:
        """
        1. 校验节点存在性
        2. 合并/替换属性
        3. 支持标签变更（REMOVE + SET label）
        4. 返回更新后节点
        """

    def delete_entity(self, element_id: str) -> None:
        """
        1. 校验节点存在性
        2. 统计关联关系数（用于前端确认提示）
        3. DETACH DELETE（删除节点 + 所有关系）
        """

    # ----- 属性 -----
    def upsert_properties(self, element_id: str, properties: dict) -> EntityResponse:
        """合并更新属性（不删除已有属性）"""

    def set_properties(self, element_id: str, properties: dict) -> EntityResponse:
        """完全替换属性（删除未传入的属性）"""

    def delete_property(self, element_id: str, key: str) -> EntityResponse:
        """删除单个属性"""

    # ----- 关系 -----
    def create_relationship(self, req: CreateRelationshipRequest) -> RelationshipResponse:
        """
        1. 校验源/目标节点存在性
        2. 校验关系类型合法性
        3. 创建关系
        4. 返回关系详情
        """

    def update_relationship(self, req: UpdateRelationshipRequest) -> RelationshipResponse:
        """更新关系属性"""

    def delete_relationship(self, rel_element_id: str) -> None:
        """删除关系"""

    # ----- 标签 -----
    def get_available_labels(self) -> list[str]:
        """获取可用标签列表（供前端下拉选择）"""

    def get_available_relationships(self) -> list[str]:
        """获取可用关系类型列表"""
```

### 3.3 校验逻辑设计

```python
# 内置校验规则（hardcoded，不依赖外部库的最小校验）

def validate_entity_name(name: str) -> bool:
    """节点名称不能为空，长度 1-200"""
    return bool(name) and len(name.strip()) > 0 and len(name.strip()) <= 200

def validate_label(label: str) -> bool:
    """标签不能含特殊字符"""
    import re
    return bool(re.match(r'^[A-Za-z\u4e00-\u9fa5][A-Za-z0-9_\u4e00-\u9fa5]*$', label))

def validate_relationship_type(rel_type: str, allowed: list[str]) -> bool:
    """关系类型必须在允许列表中"""
    return rel_type in allowed
```

**节点选择方案（本地列表 + 客户端实时筛选）**：

弹窗打开时通过 `GET /editor/nodes/search?keyword=`（空关键词）一次性加载全部节点（最多200条），存入本地 `allNodes` 列表。源节点和目标节点使用 `a-select` 组件：
- `show-search` 启用输入框
- `:options="allNodes"` 绑定全部节点
- `:filter-option="filterNodeOption"` 实现客户端大小写不敏感匹配
- 输入文字时下拉菜单实时动态筛选，无需二次请求

**编辑模式区分**：
- `mode='edit'`：编辑已有关系，源/目标节点不可更改（显示为文本），仅可修改属性和关系类型
- `mode='create'`：创建新关系，源/目标节点均可搜索选择
  - 若从左侧树关系类型分类节点触发，`presetRelationshipType` 预填关系类型字段

- 历史记录不丢失，用户在垂直滚动容器内可自由浏览

| 方法 | 端点 | 描述 | 请求体 |

| POST | `/entities/{element_id}/properties` | 批量设置属性 | `{key: value, ...}` |
| DELETE | `/entities/{element_id}/properties/{key}` | 删除属性 | — |
| POST | `/relationships` | 创建关系 | `{source_id, target_id, type, properties}` |
| PUT | `/relationships/{rel_id}` | 更新关系 | `{properties}` |
| DELETE | `/relationships/{rel_id}` | 删除关系 | — |

### 5.2 元数据接口

| 方法 | 端点 | 描述 |
|------|------|------|
| GET | `/editor/labels` | 获取所有已有标签 |
| GET | `/editor/relationship-types` | 获取所有关系类型 |
| GET | `/editor/nodes/search?keyword=` | 搜索节点（空关键词返回全部，最多200条，供关系编辑器下拉选择） |

### 5.3 请求/响应模型

```python
# models/editor.py

class CreateEntityRequest(BaseModel):
    label: str                              # 标签名
    name: str                               # 节点名称（必填）
    properties: dict[str, Any] = {}         # 其他属性

class UpdateEntityRequest(BaseModel):
    name: str | None = None                 # 更新名称
    label: str | None = None                # 更新标签
    properties: dict[str, Any] | None = None # 合并更新属性

class CreateRelationshipRequest(BaseModel):
    source_element_id: str
    target_element_id: str
    type: str                               # 关系类型
    properties: dict[str, Any] = {}

class UpdateRelationshipRequest(BaseModel):
    properties: dict[str, Any] = {}

class EntityResponse(BaseModel):
    element_id: str
    labels: list[str]
    name: str
    properties: dict
    relationship_count: int                 # 关联关系数

class RelationshipResponse(BaseModel):
    element_id: str
    type: str
    source_id: str
    source_name: str
    target_id: str
    target_name: str
    properties: dict
```

## 6. 数据校验规则

### 6.1 实体校验

| 字段 | 规则 | 错误提示 |
|------|------|---------|
| `label` | 必填，只能含字母/中文/数字/下划线 | "标签格式不合法" |
| `name` | 必填，1-200 字符 | "名称不能为空（1-200字符）" |
| `properties` | key 不能重复，不能含特殊字符 | "属性名重复" / "属性名含非法字符" |

### 6.2 关系校验

| 字段 | 规则 | 错误提示 |
|------|------|---------|
| `source_id` / `target_id` | 必须是有效节点 elementId | "源/目标节点不存在" |
| `type` | 必须在已有关系类型列表中 | "关系类型不存在" |
| 重复关系 | 同一对节点 + 同一关系类型不能重复创建 | "此关系已存在" |

## 7. 交互流程设计

### 7.1 新增实体流程

```
用户右键树节点 → "新增子类"
  → 打开 EntityEditor 弹窗 (mode='create', parentElementId, presetLabel)
  → 填写名称、属性
  → 点击"保存"
  → POST /api/editor/entities
  → 成功后，若指定了 parentElementId：
      自动调用 POST /api/editor/relationships 创建 SUB_CLASS_OF 关系
  → store.refreshTree()   ← 刷新左侧树
  → store.refreshGraph()  ← 刷新右侧图谱
  → 关闭弹窗
```

### 7.2 编辑实体流程

```
用户点击详情面板 → "编辑"
  → 判断当前选中节点类型：
     - 实体节点（elementId 有效）：
       → 打开 EntityEditor 弹窗 (mode='edit', initialData)
       → 修改名称、属性
       → 点击"保存"
       → PUT /api/editor/entities/{id}
     - 关系类型分类节点（type='__RELATIONSHIP__'，无 elementId）：
       → 打开 RelationshipEditor 弹窗 (mode='create', presetRelationshipType=选中类型)
       → 选择源/目标节点
       → 点击"创建"
       → POST /api/editor/relationships
  → store.refreshTree()
  → store.refreshDetail()
  → store.refreshGraph()
  → 关闭弹窗
```

### 7.3 删除实体流程

```
用户右键节点 → "删除节点"
  → 弹出确认对话框：
     "确定删除节点「XXX」吗？
      该节点关联了 N 条关系，删除后所有关系将同时移除。
      此操作不可撤销。"
  → 用户确认
  → DELETE /api/editor/entities/{id}
  → store.refreshTree()
  → store.refreshDetail() → 清空详情面板
  → store.refreshGraph()
```

### 7.4 新增关系流程

**触发路径 A：从实体节点触发**

```
用户右键节点 → "新增关系"
  → 源节点已预设为当前节点
  → 用户选择关系类型
  → 用户在下拉菜单中搜索/选择目标节点（本地实时筛选）
  → 可选添加关系属性
  → 点击"创建"
  → POST /api/editor/relationships
  → store.refreshDetail()
  → store.refreshGraph()
  → 关闭弹窗
```

**触发路径 B：从关系类型分类节点触发**

```
用户在左侧树中选中某个关系类型分类节点（如 "HAS_SYMPTOM (5)"）
  → 点击详情面板 → "编辑"
  → 打开 RelationshipEditor 弹窗 (mode='create')
  → 关系类型自动预填为 "HAS_SYMPTOM"
  → 源/目标节点均可下拉搜索选择（本地实时筛选）
  → 点击"创建"
  → POST /api/editor/relationships
  → store.refreshTree()
  → store.refreshGraph()
  → 关闭弹窗
```

**节点下拉选择方案**：
- 弹窗打开时调用 `GET /editor/nodes/search?keyword=` 加载全部节点（最多200条）
- 源节点和目标节点使用 `a-select` 组件，`show-search` + 本地 `filterOption` 实现输入实时筛选
- 无需额外的远程搜索请求，响应即时

### 7.5 图谱画布上创建关系

```
用户在图谱画布中：
  1. 按住 Ctrl/Cmd + 点击两个节点
  2. 点击"连接"按钮
  → 打开 RelationshipEditor（源和目标已预设）
  → 选择关系类型 → 创建
```

## 9. 实施迭代优化记录

实施过程中对设计进行了以下调整和优化：

### 9.1 关系编辑器节点选择方案调整

**原设计**：源/目标节点通过远程搜索（`@search` 触发 API → `GET /editor/nodes/search?keyword=`）

**优化后**：改为本地列表 + 客户端实时筛选
- 后端 `GET /editor/nodes/search` 修改 `keyword` 参数为可选（`min_length=0`, `default=""`），空关键词返回全部节点（`LIMIT 200`，按名称排序）
- `neo4j_repository.search_nodes` 新增空关键词分支
- 前端弹窗打开时一次性调用 `searchNodes('')` 加载全部节点到本地 `allNodes` 列表
- `a-select` 使用 `:filterOption="filterNodeOption"` 实现客户端大小写不敏感筛选
- 移除远程搜索的 `searchingSource`/`searchingTarget` 状态和相关函数

**收益**：输入即时响应，无需等待网络请求

### 9.2 关系类型分类节点编辑支持

**问题**：左侧本体树中"关系"节点来自 `RelationshipCatalogItem`（关系类型目录），仅有类型名和数量信息，无具体 `elementId`。原 `handleEdit` 逻辑在检查 `!store.selectedNode.elementId` 时误判为"未选择节点"。

**解决**：
- Store 新增 `presetRelationshipType` 状态和 `openCreateRelationshipWithType(type)` 方法
- `RelationshipEditor.initFromData` 创建模式下使用 `store.presetRelationshipType` 预填类型
- `handleEdit` 新增分支：`isCategoryNode && type === '__RELATIONSHIP__'` → 打开关系编辑器创建模式
- 关闭编辑器时重置 `presetRelationshipType`

### 9.3 中间面板布局调整

- 问答区块从 40% 提升至 55%（详情区块自动占 45%）
- 输入框高度从 180px 缩小至 72px（`minRows: 2`），输入区域移除了固定最小高度限制
- 问题输入区域从垂直居中改为置于区块顶部
- 移除详情面板中独立的"新增关系"按钮（关系统一在左侧面板管理）

### 9.4 对话历史滚动

- 新增 `conversationBodyRef` DOM 引用
- 新增 `scrollToBottom()` 函数（`nextTick` 内 `scrollTop = scrollHeight`）
- 用户消息发送后和 AI 回复后各调用一次自动滚动
- `.conversation-body` 使用 `flex: 1; min-height: 0; overflow-y: auto` 撑满剩余空间
- `.query-section` 增加 `overflow: hidden` 确保高度约束生效
- 历史记录不丢失，可手动滚动查看
