## 1. 项目概述

### 1.1 项目定位

疾病本体知识图谱平台是一个基于 Neo4j 图数据库的**本体浏览与智能查询系统**。v1.0 的核心目标是：

- 以树形结构**浏览** Neo4j 中存储的疾病本体（实体、层级关系、属性）
- 通过 GraphRAG（图增强检索生成）实现**自然语言查询**
- 在可视化画布上展示 Neo4j 中的**图谱关系**

### 1.2 核心功能

| 功能模块 | 描述 | 对应前端组件 |
|---------|------|-------------|
| 本体树浏览 | 按标签分类展示节点层级，支持逐层懒加载 | `OntologyBrowser` |
| 节点详情 | 查看节点的属性、入边/出边关系 | `QueryPanel`（详情区） |
| 图谱可视化 | Force-directed 布局展示完整/邻域/最短路径图 | `GraphCanvas` |
| GraphRAG 问答 | 自然语言转 Cypher 查询 Neo4j | `QueryPanel`（问答区） |
| 面板拖拽 | 左/中面板宽度可拖拽调整，面板可折叠 | `App.vue` |

## 3. 后端设计

### 3.1 目录结构

```
backend/
├── main.py              ← FastAPI 入口，CORS + 路由注册
```

### 3.2 分层架构职责

| 层 | 职责 | 依赖方向 |
|----|------|---------|
| **Router** | HTTP 路由注册、参数提取、调用 Service、HTTP 响应 | → Service |
| **Service** | 业务逻辑编排、数据模型构建、聚合展开逻辑 | → Repository |
| **Repository** | 原生 Cypher 执行、Neo4j 连接管理、结果字典返回 | → Neo4j |

### 3.3 依赖注入模式

## 5. 数据模型

### 5.1 核心 Pydantic 模型

#### 本体树相关

```python
class NodeInstance(BaseModel):
    element_id: str        # Neo4j 内部 ID
    name: str              # 节点名称
    labels: list[str]      # 标签列表
    child_count: int = 0   # 子类数量（0 = 叶节点）

class NodeTypeInfo(BaseModel):
    label: str             # 标签名
    count: int             # 该标签节点总数
    properties: list[PropertyDetail]
    instances: list[NodeInstance]

class OntologyTree(BaseModel):
    node_types: list[NodeTypeInfo]
    relationship_types: list[RelationshipCatalogItem]
```

#### 节点详情

```python
class NodeDetail(BaseModel):
    element_id: str
    labels: list[str]
    properties: dict
    incoming_relationships: list[RelationshipItem]
    outgoing_relationships: list[RelationshipItem]
```

#### 图谱相关

```python
class GraphData(BaseModel):
    nodes: list[GraphNode]     # {id, label, type, color}
    edges: list[GraphEdge]     # {id, source, target, type, label}
    meta: GraphMeta            # {total_nodes, total_edges}
```

### 5.2 Neo4j 数据模式

#### 节点标签

| 标签 | 颜色 | 说明 |
|------|------|------|
| Disease | 红 `#f5222d` | 疾病 |
| Symptom | 橙 `#fa8c16` | 症状 |
| Drug | 蓝 `#1890ff` | 药物 |
| BodyPart | 绿 `#52c41a` | 身体部位 |
| SideEffect | 紫 `#722ed1` | 副作用 |

#### 关系类型

| 关系 | 说明 | 方向 |
|------|------|------|
| SUB_CLASS_OF | 本体层级（子类→父类） | 疾病层级 |
| MANIFESTS_IN | 症状表现为某疾病 | Symptom → Disease |
| AFFECTS | 疾病影响某部位 | Disease → BodyPart |
| HAS_SIDE_EFFECT | 药物有副作用 | Drug → SideEffect |
| CONTRAINDICATED_WITH | 药物禁忌 | Drug → Drug |
| CAN_SUBSTITUTE | 药物可替代 | Drug → Drug |

## 7. 核心功能详解

### 7.1 本体树懒加载机制

```
1. 页面加载 → GET /api/ontology/tree → 获取各标签的根节点列表
2. 后端 Service 自动展开"聚合节点"：
   - 若根节点 child_count > 0（如"疾病"），将其子类提升到根层级
   - 若根节点 child_count = 0（如"青霉素过敏"），保持为叶子节点
3. 前端构建 TreeNode，有 elementId 且 childCount > 0 的节点设为 isLeaf=false
4. 用户展开 → onLoadData → GET /nodes/{id}/subclasses → 返回子节点 + child_count
5. 子节点注入 dataRef.children，设置 isLeaf 状态
```

**关键修复**：`treeNodeData` 用 ref 缓存，Watch `treeData` 变化时重建，避免重渲染丢失懒加载数据。

### 7.2 GraphRAG 问答流程

```
用户输入 → POST /api/query {question}
  → QueryService:
      1. LangChain Neo4jGraph 提取 Schema
      2. GraphCypherQAChain 将自然语言 → Cypher（带自定义提示词）
      3. 在 Neo4j 执行 Cypher 查询
      4. LLM 将查询结果格式化为自然语言回答
  → 返回 {answer, cypher, raw_data}
```

**自定义 Cypher 提示词规则**：
- 所有数据为中文，英文提问需翻译关键实体
- 节点匹配使用 `CONTAINS` 而非 `=`
- 大类查询需通过 `SUB_CLASS_OF*1..3` 递归查找子类
- 关系方向必须匹配 Schema 定义

### 7.3 图谱可视化

- 基于 **vis-network** 的 Force-directed 布局
- 支持三种模式：
  1. **总览**：展示所有节点和关系
  2. **邻域**：以选中节点为中心，展开 depth 层关系
  3. **最短路径**：展示两个节点之间的最短关系路径
- 节点颜色按标签类型着色，与左侧本体树的色系一致

## 8. 部署指南

### 8.1 环境要求

- Python 3.10+
- Node.js 18+
- Neo4j 5.x（需开启 bolt 连接）

### 8.2 后端启动

```bash
cd backend
pip install -r requirements.txt
cp .env.example .env  # 编辑 Neo4j 和 LLM 配置
uvicorn backend.main:app --host 0.0.0.0 --port 8080
```

### 8.3 前端启动

```bash
cd frontend
npm install
npm run dev  # Vite dev server → http://localhost:3000
```

### 8.4 环境变量

| 变量 | 说明 | 示例 |
|------|------|------|
| NEO4J_URI | Neo4j bolt 地址 | bolt://localhost:7687 |

| NEO4J_PASSWORD | 密码 | neo4j |
| LLM_API_KEY | LLM API Key | sk-xxx |
| LLM_MODEL | 模型名 | glm-5.2 |
