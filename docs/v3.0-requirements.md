## 1. 背景与目标

### 1.1 背景

v2.0 实现了基于 Neo4j 的单领域知识图谱系统，专注于"疾病-症状-药物-身体部位"领域。系统支持本体浏览、图谱可视化、GraphRAG 智能问答及在线编辑。

### 1.2 v3.0 核心目标

**从单领域固定知识图谱升级为通用可配置的多领域知识图谱平台。** 用户可自行导入任意领域的数据，快速构建新的知识图谱系统，并在多个系统之间自由切换。

## 2. 功能需求

### 2.1 多系统支持（Multi-System / Multi-Tenant）

**FR-01 系统概念**

- 每个独立的知识图谱数据集合称为一个"系统"（System）
- 每个系统拥有独立的：本体树、实体数据、关系数据、图谱可视化
- 当前已有的"疾病本体知识图谱"作为默认系统保留
- 新导入的数据自动创建新系统

**FR-02 系统切换器**

- 位置：前端页面顶部 Header 区域，当前标题"疾病本体知识图谱平台 v2.0"处改为下拉选择框
- 下拉框展示所有已存在的系统名称
- 选择不同系统后，整个前端界面（本体树、详情面板、知识图谱、问答）全部切换到对应系统的数据
- 切换时保持当前的 UI 状态（折叠/展开、面板宽度等）

**FR-03 系统元数据**

- 每个系统包含以下元信息：
  - 系统名称（用户自定义）
  - 系统描述
  - 创建时间
  - 数据来源（Excel / MySQL 等）
  - 实体数量、关系数量、关系类型数量

### 2.2 数据导入

**FR-04 Excel 导入**

- 入口：Header 区域"导入新数据"按钮 → 下拉菜单 → "从 Excel 导入"
- 功能流程：
  1. 用户点击按钮，弹出导入向导对话框
  2. 步骤一：上传 Excel 文件（支持 .xlsx / .xls）
  3. 步骤二：系统解析 Excel，展示预览数据（实体列表、关系列表）
  4. 步骤三：用户确认后，系统将数据写入 Neo4j，创建新系统
  5. 完成后自动切换到新系统

- Excel 格式规范（见 FR-07 模板）

**FR-05 关系数据库导入（MySQL）**

- 入口：Header 区域"导入新数据"按钮 → 下拉菜单 → "从 MySQL 导入"
- 功能流程：
  1. 用户填写 MySQL 连接信息：Host、Port、Database、Username、Password
  2. 测试连接
  3. 选择要导入的表
  4. 配置映射关系：
     - 哪些表映射为实体（需指定 name 列和 label）
     - 哪些表映射为关系（需指定 source 列、target 列、关系类型）
     - 额外属性列映射
  5. 预览并确认后导入

**FR-06 关系数据库通用导入（基于 SQLAlchemy）**

- 入口：Header 区域"导入新数据"按钮 → 下拉菜单 → "从其他数据库导入"
- 通过 SQLAlchemy 的数据库方言（Dialect）机制，统一接入多种关系数据库
- 支持数据库类型：MySQL、PostgreSQL、SQL Server、Oracle、SQLite 等
- 用户仅需选择数据库类型 + 填写连接信息（Host、Port、Database、User、Password），无需关心底层驱动差异
- 流程与 MySQL 导入类似：连接测试 → 选择表 → 配置映射 → 预览 → 导入

**FR-07 导入数据模板**

- 入口：Header 区域"模板"按钮
- 功能：
  - 点击弹出模板说明对话框
  - 提供 Excel 模板文件的下载链接
  - 模板中包含示例数据（当前疾病系统的数据作为样例）
  - 模板含多个 Sheet：
    - **Sheet 1: 实体定义（Entities）**
      - 列：`label`（实体类型）、`name`（实体名称）、`properties`（其他属性，格式：key1=value1;key2=value2）
    - **Sheet 2: 关系定义（Relationships）**
      - 列：`source_label`、`source_name`、`type`（关系类型）、`target_label`、`target_name`、`properties`
    - **Sheet 3: 说明（Readme）**
      - 各列的填写规范、注意事项

- 模板中预填当前疾病系统数据作为示例：
  - 实体示例：`Disease | 肺炎 | icd_code=J18.9;category=呼吸系统`
  - 关系示例：`Drug | 阿莫西林 | TREATS | Disease | 肺炎 | dosage=500mg`

### 2.3 系统管理

**FR-08 系统删除**

- 在系统切换器下拉框旁有"管理"入口
- 可删除非当前系统（需二次确认）
- 删除系统会移除其 Neo4j 中的所有对应数据

**FR-09 系统更名**

- 在系统管理界面可修改系统名称和描述

## 3. 非功能需求

### 3.1 性能

- 系统切换响应时间 < 1 秒
- Excel 导入（1000 条实体 + 5000 条关系）< 30 秒
- MySQL 大批量导入使用批处理，避免 Neo4j 事务超限

### 3.2 数据隔离

- 不同系统的数据在 Neo4j 中完全隔离
- 查询、编辑、删除操作仅作用于当前选中系统
- 系统间的数据不能互相污染

### 3.3 兼容性

- 现有 v2.0 的疾病系统数据无需迁移，自动成为默认系统
- 前端现有所有功能（本体浏览、图谱、问答、编辑）在新系统上无需改动即可复用

### 3.4 扩展性

- 导入模块设计为可插拔架构，后续可扩展更多数据源
- 模板格式保持向下兼容

## 5. 验收标准

| 编号 | 验收条件 |
|------|----------|
| AC-01 | Header 中系统切换下拉框正常显示所有系统，切换后全界面数据正确切换 |
| AC-02 | 默认"疾病本体知识图谱"系统数据与 v2.0 完全一致，原有功能无退化 |
| AC-03 | Excel 导入后自动创建新系统，新系统中本体树、图谱、问答功能均正常 |
| AC-04 | 模板按钮可下载标准 Excel 模板，模板中预填疾病系统示例数据 |
| AC-05 | MySQL 导入流程完整可用（连接 → 选表 → 映射 → 导入） |
| AC-06 | 关系数据库通用导入至少支持 PostgreSQL 和 SQL Server（连接 → 选表 → 映射 → 导入） |
| AC-07 | 删除系统后 Neo4j 中对应数据被正确清理，不影响其他系统 |
| AC-08 | 编辑功能（实体/关系增删改）在不同系统间正确隔离 |
